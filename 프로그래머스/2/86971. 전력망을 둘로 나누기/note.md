## 🔍 문제 요약 (30초 컷)
- 입력: 송전탑 개수 `n`, 송전탑을 연결하는 전선 `wires`
- 출력: 전선 하나를 끊어 두 전력망으로 나눴을 때 송전탑 개수 차이의 최솟값
- 핵심 제한: `n ≤ 100`, 주어진 전력망은 **연결된 무방향 트리**, 간선 수는 `n - 1`

👉 한 줄 요약: **트리의 간선 하나를 제거했을 때 생기는 두 connected component의 크기 차이 최솟값을 구하는 문제**

---

## 🧠 접근 흐름 (사고 과정 기록)
1. 처음 접근: 각 노드의 하위 노드 개수를 미리 계산하고, 전체의 절반에 가장 가까운 subtree를 찾아 해당 subtree를 분리하려 했다. 매번 전선을 끊고 다시 탐색하지 않아도 된다고 생각했다.
2. 막힌 지점: 일반적인 `tree`에 처음부터 root와 parent/child 관계가 있다고 잘못 가정했다. 또한 DFS에서 `visited`를 방문 여부와 subtree size 용도로 동시에 사용하여 올바른 subtree size를 계산하지 못했다.
3. 수정한 방향: 실전에서는 제한이 작으므로 **각 간선을 하나씩 제거 → DFS로 한쪽 component 크기 계산 → 복구**하는 단순한 `O(N²)` 풀이를 사용한다. 기존 아이디어를 발전시키려면 임의의 root를 정하고 DFS 한 번으로 모든 `subtreeSize`를 계산하는 `O(N)` 풀이가 가능하다.

---

## 💡 핵심 아이디어 (진짜 중요)
👉 이 문제의 본질 = **트리에서 간선 하나를 제거하면 정확히 두 개의 connected component로 나뉜다는 성질을 이용하는 것**

- 핵심 패턴: `간선 제거 → connected component 크기 계산 → 두 크기 비교`
- 사용한 자료구조: 인접 리스트, DFS용 Stack/visited
- 시간복잡도: 간선마다 DFS를 수행하면 `O(N²)` / subtree size를 미리 계산하면 `O(N)`

---

## ❌ 실패 원인 (팩트만)
- 오해한 조건: `Tree = root와 parent/child가 이미 정해진 구조`라고 생각함. 실제 입력은 **root가 지정되지 않은 undirected tree**.
- 잘못된 선택: 가장 많은 자식을 가진 노드를 root로 찾으려 했고, `visited`만으로 parent/child 관계와 subtree size를 동시에 판단하려 함.
- 불필요한 연산: `n/2`에 가까운 subtree를 찾기 위해 BFS를 사용함. root와의 거리는 정답과 관계없으므로 BFS가 필요하지 않음.

---

## ✅ 정답 접근 요약 (재사용 가능하게)
- 흐름:
    1. 무방향 트리를 인접 리스트로 만든다.
    2. 모든 간선을 하나씩 제거하고, 한쪽 끝점에서 DFS하여 component 크기 `count`를 구한 뒤 간선을 복구한다.
    3. 다른 쪽 크기는 `n - count`이므로 `|count - (n - count)|`의 최솟값을 갱신한다.

👉 외워야 할 형태:  
**트리에서 간선 하나 제거 → 정확히 두 component 생성 → 한쪽 크기만 DFS로 구함 → 다른 쪽은 `전체 - 한쪽`**

---

## 🔁 트리거 (패턴 인식용)
👉 **“트리에서 간선 하나를 제거한다”가 나오면 → 두 connected component로 나뉜다는 성질을 먼저 떠올린다**

- 예:
    - “트리의 간선 하나 제거” → 두 connected component
    - “한쪽 component 크기” → DFS/BFS로 연결된 노드 수 세기
    - “두 그룹의 크기 비교” → 한쪽이 `count`이면 다른 쪽은 `n - count`
    - “subtree 정보가 필요함” → 임의의 root를 정한 뒤 Tree DFS로 subtree aggregation 고려
