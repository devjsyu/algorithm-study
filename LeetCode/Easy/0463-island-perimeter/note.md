## 🔍 문제 요약 (30초 컷)
- 입력: `0`은 물, `1`은 육지를 나타내는 2차원 Grid
- 출력: 섬의 전체 둘레
- 핵심 제한: 육지는 상하좌우로 연결되며, 각 육지 칸의 변 중 물 또는 Grid 외부와 맞닿은 변이 둘레가 된다.

👉 한 줄 요약: **각 육지 칸에서 물 또는 Grid 외부와 맞닿아 있는 변의 개수를 구하는 문제**

---

## 🧠 접근 흐름 (사고 과정 기록)
1. 처음 접근:
    - Grid 자체를 그래프로 보고 BFS를 선택했다.
    - 최초의 육지 칸을 찾아 BFS를 시작했다.
    - `visited` 배열을 사용하여 이미 탐색한 육지를 다시 방문하지 않았다.
    - 현재 육지의 상하좌우를 확인하여 Grid 밖이거나 물이면 둘레를 `+1` 했다.

2. 고민한 지점:
    - BFS를 사용하면 연결된 육지만 탐색하므로 전체 Grid를 순회하는 것보다 효율적일 수 있다고 생각했다.
    - 하지만 BFS를 위해 `visited`, `Queue`, 좌표 객체 등의 추가 자료구조가 필요했다.
    - 이 문제에서는 섬의 연결 관계나 최단거리 자체를 구할 필요가 없다는 점을 놓쳤다.

3. 수정한 방향:
    - 모든 육지 칸은 독립적으로 자신의 둘레 기여도를 계산할 수 있다는 점을 이용한다.
    - Grid를 단순 순회하면서 육지의 상하좌우가 Grid 밖 또는 물인지 확인한다.
    - 따라서 BFS/DFS와 `visited` 없이도 해결할 수 있다.

---

## 💡 핵심 아이디어 (진짜 중요)

👉 이 문제의 본질 = **탐색이 아니라 각 육지 칸이 둘레에 기여하는 변을 세는 것**

- 핵심 패턴: Grid 순회 + 인접 칸 검사
- 사용한 자료구조: 별도의 자료구조 필요 없음
- 시간복잡도: `O(rows × cols)`
- 추가 공간복잡도: `O(1)`

각 육지 칸의 상하좌우를 확인한다.

- Grid 밖 → 둘레 `+1`
- 물(`0`) → 둘레 `+1`
- 육지(`1`) → 둘레 증가 없음

## ❌ 실패/개선 포인트 (팩트만)
- 오해한 조건:
    - Grid 문제이고 육지가 연결되어 있으므로 BFS가 적합하다고 생각했다.
    - 하지만 **BFS로 풀 수 있다는 것과 BFS가 필요한 것은 다르다.**

- 불필요한 선택:
    - 시작 육지를 찾기 위한 별도 순회
    - `boolean[][] visited`
    - `Queue<int[]>`
    - BFS 과정에서의 좌표 배열 생성 및 Queue 연산

- 성능에 대한 오해:
    - `visited`를 사용하면 모든 Grid를 순회하지 않을 수 있으므로 특정 입력에서는 BFS가 실제로 더 빠를 수도 있다.
    - 그러나 `visited` 역시 생성·초기화·접근 비용이 있으며 BFS에는 Queue 관리 등의 추가 작업이 필요하다.
    - 둘 다 최악의 시간복잡도는 `O(rows × cols)`이다.
    - 단순 순회는 추가 공간 `O(1)`로 더 간단하게 해결할 수 있다는 장점이 있다.
    - `new int[]{r, c}` 같은 단명 객체는 현대 JVM이 비교적 효율적으로 처리하지만 비용이 0인 것은 아니며, 이 문제에서는 애초에 생성할 필요가 없다.

## ✅ 정답 접근 요약 (재사용 가능하게)
- 흐름:
    1. 전체 Grid를 순회한다.
    2. 물이면 건너뛴다.
    3. 육지라면 상하좌우 4방향을 검사한다.
    4. 인접 위치가 Grid 밖이거나 물이면 둘레를 `+1` 한다.

👉 외워야 할 형태:

**Grid 문제를 보면 바로 BFS/DFS를 선택하지 않는다.**

먼저 다음을 판단한다.

**“연결 관계나 경로를 실제로 탐색해야 하는가?”**

아니면

**“각 칸을 독립적으로 검사해서 답을 계산할 수 있는가?”**

각 칸의 지역적인 정보만으로 답을 계산할 수 있다면 단순 Grid 순회를 먼저 고려한다.

---

## 📝 이번 문제에서 가져갈 교훈

**탐색이 가능하다는 것과 탐색이 필요하다는 것은 다르다.**

BFS/DFS는 연결 요소, 도달 가능성, 경로, 거리 등을 알아내야 할 때 강력하다.

하지만 현재 칸과 주변 칸의 관계만으로 답을 계산할 수 있다면 BFS/DFS 없이 단순 순회가 더 적합할 수 있다.

또한 Big-O가 같다고 실제 비용까지 같은 것은 아니다. 자료구조 생성, Queue 연산, 객체 생성, 메모리 접근 같은 추가 작업도 고려해야 한다.
