## ❌ [FAIL / SO-SO] 최초 접근 로직
### 🤔 생각한 흐름:
* 스택 자료구조를 구현하면서 최소값을 찾아야 하겠구나
* 순회를 통한 단순 비교는 Linear time이 걸릴 테고, 정렬은 NlogN time이 걸릴 테니, 다른 방식을 생각해야 한다
* 매번 push할 때마다 최소값을 갱신하면 constant time이 걸릴 것이다
* 원시자료형 배열로 자료구조를 구현한다면 배열의 크기 resizing 문제가 불필요하게 복잡해질 것이다.
  * 메서드 호출을 30만번 이상 한다고 했기 때문이다.
* 스택 자료구조를 구현할 때, ArrayList를 사용하면 배열의 크기에 제약 받지 않을 것이다.
  * (자료구조 책에서 흔히 보이는 size, ptr 등 변수를 직접 관리해야만 한다고 생각했음)
* pop 하는 순간 최소값이 변경될 수 있는데 이건 어떻게 해결해야 할까?
  * 최소값만을 담는 보조 스택을 운용한다면?

### ⚠️ 왜 비효율적/실패했는가?:
* `LinkedList` 형식이 아니라 `ArrayList` 형식이라서 인덱스 등 변수를 직접 관리해야 했고, 거기서 실수가 발생해서 고치는 데에 한참 걸렸다!
* 최소값만을 담는 보조 스택을 사용한다는 아이디어는 나름 참신했으나, 매번 최소값 갱신을 검사해야 했고, 오버헤드 비용으로 인해 공간복잡도도 불리할 것이다.

## ✅ [SUCCESS] 정답/모범답안 로직
### ✨ 수정된 흐름:
* 임의의 클래스 `Node`를 정의한다. int value, int min, pointer(해당 클래스 `Node` 타입)
  * Stack이기 때문에 pointer는 다음 노드가 아니라, 이전 노드를 가리킨다.
  * 각 노드마다 최소값을 계산되었고, 후입선출 구조에서 각 노드에서 기억하는 최소값은 정확하다.
